# 0006. UX: live indicator, streaming markdown, live command output, the typed line in the scrollback

- Status: accepted
- Date: 2026-09-29
- Milestone: M7

## Context

M7 makes ecdy pleasant to use without weakening invariants 1 and 2. Five choices need a record:

1. **The classification indicator** (ROADMAP: `zle-line-pre-redraw` + RPROMPT, "only cheap checks on
   the zsh side"). A zsh-only guess (first word's kind, a `?` prefix, non-ASCII letters) is cheap
   but disagrees with Enter exactly where it matters: `rm everything in tmp except configs` starts
   with a known command and would be shown as a command, while Enter opens the Ask dialog. A copy
   of the classifier in zsh would drift from the Go one.
2. **Markdown.** AGENTS.md section 5 says markdown is rendered as it arrives. glamour, the allowed
   library, renders whole documents only: `TermRenderer.Write` buffers and `Render`/`Close` render
   everything (read in `glamour.go`, v2). Using it would mean splitting the stream into blocks
   ourselves and rendering each when it ends, so text would appear a paragraph at a time and a code
   block only once it is closed; it also brings goldmark, chroma and lipgloss v2 into the binary
   that `ecdy classify` cold-starts on every Enter.
3. **Command output while a command runs** (ADR 0005 left it to M7): with `-v`, codex's and pi's
   output arrives in `_meta` while the command runs, but is shown only after it finishes.
4. **The scrollback** shows the rewritten `ecdy ask -- '...'` line instead of what was typed (M2).
   Whatever ZLE displays last is what runs: a test on zsh 5.9 shows ZLE redrawing the buffer once
   more after `zle-line-finish`, so the buffer cannot be shown as one text and run as another.
5. **`ecdy doctor`** must check the shell as well: which widget Enter runs, what Alt+Enter and `?`
   are bound to, whether a plugin loaded later took them. A binary cannot see its parent shell's
   widgets and keys, and a fresh `zsh -i` would read `.zshrc` again without the state of the
   shell the user is in (zsh-vi-mode, for one, sets itself up at the first prompt). The
   compatibility tests (zsh-vi-mode, fzf-tab, atuin) found what to look for: atuin 18.15+ binds
   `?` to its AI mode, which takes ecdy's `?` prefix, and records every prompt as
   `ecdy ask -- '…'`; fzf-tab's optional `accept-line` key accepts through `.accept-line`,
   skipping ecdy's classifier.

## Decision

**Indicator: the real classifier, asynchronously.** On every redraw where the buffer changed
(`zle-line-pre-redraw`, through `add-zle-hook-widget`), the plugin starts `ecdy classify` in the
background, with the same arguments as Enter, and watches its output with `zle -F` (the way
zsh-autosuggestions' async mode works). A classifier still running for an older buffer is killed.
When the answer comes, the verdict is put in front of the user's RPROMPT and the prompt is redrawn
(`zle reset-prompt`, only if the text changed). Typing never waits for ecdy: the cost is one
background fork per change. Enter still classifies synchronously, so the indicator is advice and
never decides what runs; it shows what Enter will do because it is the same code with the same input.
Invariant 2: a missing, failing or slow binary shows no indicator and changes nothing else.
Settings: `ECDY_INDICATOR=off` disables it (no hook, no forks); `ECDY_INDICATOR_PROMPT`,
`ECDY_INDICATOR_ASK`, `ECDY_INDICATOR_CMD` are prompt strings for each verdict (the last one empty
by default: commands are the normal case); `ECDY_VERDICT` holds the last verdict for themes that
draw their own right prompt (`ECDY_INDICATOR=var` then leaves RPROMPT alone).

**Markdown: ecdy's own streaming renderer, no dependency.** A small state machine in
`internal/render` renders the agent's message text as it arrives when the output is a terminal
with colors: headings, emphasis, inline code, fenced code blocks, lists, block quotes, rules,
links (text underlined, URL dimmed after it) and backslash escapes. It holds back only what it
cannot decide yet (a line's first characters, a delimiter at the end of a chunk, a link's text up
to its `)`, an emphasis or code span opener until its closer arrives), at most one line. An
opener that is not closed on its line is printed as it is, as CommonMark does: `$((6*7))` in a
reply must keep its `*`. The output does not depend on how the text is split into chunks (tested
by splitting at every position, and fuzzed). Styles end at every line end and before any dialog or
notice. Tables, HTML and nested structures are printed as they are; there is no syntax highlighting
and no reflow. On a terminal the renderer also drops escape sequences and control characters from
the agent's text, which is printed raw today: a reply quoting a file must not drive the terminal.
Piped output stays raw markdown.

**Live command output with `-v` on a terminal.** While a tool call is running and is the last thing
printed, the last 5 lines of its `_meta` output are drawn under its status line and redrawn as
output arrives; each line is cut to the terminal width, so each takes exactly one row and the
region can be erased by moving up. Anything else printed (text, another tool call, a notice, a
dialog) erases the region first. When the command finishes, the final lines are printed as in M6.

**The typed line in the scrollback.** Right after a prompt's line is accepted, ZLE has drawn the
rewritten line. In `zle-line-finish` the plugin moves the cursor to the start of the buffer
(`CURSOR=0; zle -R`) and writes the original line over it, followed by "clear to the end of the
screen", saving and restoring the cursor around it (`ESC 7` / `ESC 8`). The original line is shorter
than the rewritten one, which is already on screen, so the write cannot scroll and the restored
position is right. ZLE's last redraw then finds nothing to change and only moves to the next line.
If the rewritten line wrapped to more rows than the original, a blank row may be left before the
output. Only the display changes: the rewritten line is still what runs.

The rewritten line would still flash for a frame between ZLE's redraw after `accept-line` and the
write in `zle-line-finish`. So the plugin turns on synchronized output (DEC private mode 2026:
`CSI ? 2026 h` … `CSI ? 2026 l`) right after it rewrites the buffer, and turns it off at the end of
`zle-line-finish`. A terminal that supports the mode shows only the final screen, with the typed
line. Others ignore it. `preexec` and `precmd` also turn it off, in case `zle-line-finish` did not
run, e.g. for a line dropped after the rewrite.

**`ecdy doctor`: offline checks, the shell reported by the plugin, agents on request.** The
plugin defines a function `ecdy` in front of the binary (only if no function or alias of that
name exists); for `ecdy doctor` it passes a few key=value lines about the shell in
`ECDY_DOCTOR_ZSH`, for everything else it runs the binary unchanged. The checks themselves are
pure Go (`internal/doctor`). Without that variable doctor still checks the binary, the config, the
agents' commands and zsh, and says the shell was not checked. `--agents` starts each agent for
`initialize` and `session/new` only, in parallel with a timeout, to find a missing login
(`auth_required`); it never sends a prompt, and it is opt-in because it starts the agents'
processes (npx may download them). Exit status 1 when a check fails, 0 with warnings only.

## Consequences

- One `ecdy classify` per buffer change runs in the background while typing (killed when the
  buffer changes again), about 5 ms of CPU each; `ECDY_INDICATOR=off` removes it.
- `zle reset-prompt` re-expands the user's prompt each time the indicator changes, which is costly
  with a slow prompt; it happens only when the verdict changes, not on every key.
- The markdown renderer is a subset: tables, nested lists and HTML are shown as source; emphasis
  and code spans do not cross lines. After an opener such as `*`, the rest of the line appears
  when the closer arrives or the line ends, not character by character. The chunk-independence
  test and the fuzz test guard the state machine.
- The agent's text is sanitized on a terminal; `ecdy ask … | cat` still gets the exact text.
- Live output needs the terminal width; a resize during a command may leave a stale row, the final
  output after the command is unaffected.
- The typed line in the scrollback loses the syntax highlighting it had while typing.
- In a shell with the plugin, `ecdy` is a function; `whence -w ecdy` says so, and
  `command ecdy doctor` skips the shell checks.
